# Ash-Tech pre-launch audit

## Overall assessment

**Not ready for invited-user private use until the backend and operational blockers below are
cleared.** This project is a private, owner-provisioned site for a small set of permanent or
temporary users; public signup, search indexing, public marketing SEO, payments, and public UGC
moderation are out of scope. The source now has protected routes, explicit provisioned-user
checks, RLS policies, CSP, and API input protections. The schema has now been applied to the
confirmed staging project: all five app tables respond through PostgREST, RLS is enabled on
each with one policy, and `entry-images` is private. The confirmed owner is provisioned in
staging and `ASH_OWNER_EMAIL` is set locally. Still unresolved are the credential-shaped token
in Git history, authenticated app/user provisioning and isolation tests, hosting-secret
verification, backups/recovery, and privacy information for invited users.

Status legend: ✅ handled in source or verified locally; ⚠️ partial, conditional, or not
verified in the deployed environment; ❌ missing; N/A not applicable to the current
private, no-payment product.

1. Schema installation, initial RLS/private-bucket configuration, trusted owner metadata, local `ASH_OWNER_EMAIL`, owner Google sign-in, and a basic owner create/read/soft-delete smoke test are verified on isolated staging. 6. Ensure the privacy/cookie/terms notices accurately explain this private invited-user service, its providers, retention, and contact route. Capture Terms acceptance if required for your invited users; public signup checkbox requirements do not apply unless public signup is introduced.
